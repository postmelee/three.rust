# Pinned Fox real-asset replay

Source: [Khronos glTF Sample Assets, Fox](https://github.com/KhronosGroup/glTF-Sample-Assets/tree/15cd02d304e54cb42a4db4eefe719f76190f4b68/Models/Fox).

Adaptation: this is a new benchmark application, not an unmodified upstream example. Geometry, skin weights, materials, texture and all three animation clips remain original. Scale/placement, lighting, camera and deterministic normal-weight blending are application changes, identical across paths. The asset's three clips animate overlapping joints; blending here is an explicit Three.js application policy, not a glTF playback requirement. No model binary changes. Existing `fixtures/original/` and synthetic rigs are unchanged.

`descriptor.mjs` accepts only the audited one-mesh, identity-bind, parent-before-child, opaque, linear TRS joint-animation subset. It rejects unsupported mesh transforms, non-joint ancestor transforms, morphs, multiple materials, transparent materials, additive and non-linear/arbitrary bindings. It is not a general glTF importer. Fox has 24 joints and 21 tracks per clip (Survey, Walk, Run). A separate original Three.js object graph is created for each baseline rig; the owned paths acquire numeric descriptors and use the existing prepared-palette renderer. Upstream work is poisoned during owned correctness checks.

Replay repeats every 600 fixed ticks at 1/60 simulation seconds. Ticks 0–119 walk; 120–179 pause; 180–299 externally blend walk into run; 300–419 run; 420–479 stop (zero weights, seek zero, paused, rest pose); 480–599 restart Survey. Root translation and camera orbit are deterministic; every 60th tick reads a complete synchronous snapshot inside the main CPU timer. Static-one uses the rest pose and fixed camera with the same read cadence. Stop is the explicit composition of supported commands, not full `AnimationAction.stop()` identity/event semantics. No crossFadeTo scheduling, warping, additive/cubic/morph/material tracks, events, raycasts or CPU animated bounds are claimed. They remain unsupported and are covered by rejection tests for the finite owned API.

All paths render 640×480 DPR1, antialias off, preserved drawing buffer, opaque original material, equal lighting and no shadows. The conservative bound/sort-point policy is identical; draw and triangle parity are checked. The 16-rig variant is a scalability workload, not an original-size asset claim. Browser frame CPU includes input creation/validation, commands, evaluation, requested snapshots, palette/root copies and renderer return. GPU completion and screenshot capture are outside the timer. Instrumented diagnostics split evaluate, copy/preparation, read and renderer submission; the upstream preparation includes world/palette calculation while owned preparation copies final buffers, so these labels describe boundaries rather than equal algorithms.

Correctness uses exact A/A pixels, all numeric buffers and camera matrices at 11 input checkpoints. Before measurements, alternate-path raster tolerance is fixed at <0.1% differing RGBA channels and mean absolute channel error <0.02 (8-bit); numeric tolerance is 2e-5 + 1e-6 × reference magnitude. This accommodates sparse raster edges from f64 arithmetic, not missing material/geometry. Captures are reviewed separately from timings.

## Observed raw quaternion representation difference

The first real-asset correctness run rejected component-wise pose equality during the zero-weight stop phase. Investigation showed two joints with exactly antipodal quaternions (q versus -q); world matrices, palettes and actions matched. r186 PropertyMixer retains an accumulator hemisphere when mixing fully back to rest, whereas the owned evaluator directly restores its descriptor base quaternion. Both encode the same rotation and render identically, but raw snapshot components are not identical. The oracle now compares quaternion rotations modulo sign while recording every sign flip and raw maximum difference; no engine code or rendered pose is changed. Applications requiring component-sign continuity or ordinary Bone identity must use the upstream facade. The failed check is preserved and this is a compatibility limitation, not silently dropped data.
